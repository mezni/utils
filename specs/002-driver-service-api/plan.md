# Implementation Plan: Driver Service & Spatial API

**Branch**: `002-driver-service-api` | **Date**: 2026-06-17 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/002-driver-service-api/spec.md`

## Summary

Build the Rust Actix-web driver-service — a geospatial read API serving nearby charging stations via `/api/v1/nearby`, a `/health` endpoint for orchestration, structured JSON logging, and Traefik gateway routing. Depends on Sprint 1.1's PostGIS function `gis.get_nearby_stations()` and the running `platform_db`.

## Technical Context

**Language/Version**: Rust 1.96.0 (stable, installed)

**Primary Dependencies**: 
- `actix-web` — HTTP framework
- `actix-rt` — Tokio-powered async runtime
- `sqlx` (with `postgres` + `runtime-tokio` + `tls-native-tls`) — database connectivity  
- `serde` / `serde_json` — JSON serialization
- `tracing` / `tracing-subscriber` — structured JSON logging
- `config` — environment-based configuration
- `dotenvy` — `.env` file loading

**Storage**: PostgreSQL 16 + PostGIS (`platform_db`), read-only queries via `gis.get_nearby_stations()`

**Testing**: `cargo test` — Actix-web test helpers for HTTP integration tests; sqlx `query_as!` compile-time checks

**Target Platform**: Linux x86_64 (Docker container, `debian:bookworm-slim`)

**Project Type**: Web service (REST API)

**Performance Goals**: 
- Warm nearby query <100ms p95
- Health endpoint <50ms
- Cold start <5s (including connection pool establishment)

**Constraints**: 
- Compile-time verified SQL queries (`sqlx::query_as!`)
- Enforce 200 km max radius
- Structured JSON logging to stdout only (no log files)
- Connection pool: min 1, max 10 (configurable)
- CORS allow-all during validation

**Scale/Scope**: 10 seed stations; up to 50 concurrent users in validation
