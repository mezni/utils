# Data Model: MVP-1 Foundation Setup

**Date**: 2026-06-08
**Source**: Feature spec + constitution sections 4, 5, 8

## Entities

### Partner

An organization that owns and operates EV charging stations.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| id | number | yes | Auto-generated by json-server |
| name | string | yes | Organization name |
| phone | string | no | Contact phone number |
| email | string | no | Contact email address |

**Relationships**: Has many `Station` instances (via `station.partner_id`)

---

### Station

A physical EV charging location with geographic coordinates.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| id | number | yes | Auto-generated by json-server |
| name | string | yes | Station display name |
| partner_id | number | yes | FK to `Partner.id` |
| latitude | number | yes | Decimal degrees (WGS84) |
| longitude | number | yes | Decimal degrees (WGS84) |
| address | string | yes | Street address in Tunisia |
| status | string | yes | One of: `available`, `in_use`, `maintenance` |

**Status values**:
- `available` — Station is operational and has free chargers
- `in_use` — All chargers currently occupied
- `maintenance` — Station is temporarily unavailable

**Relationships**: Belongs to one `Partner`. Has many `Charger` instances (via `charger.station_id`)

---

### Charger

An individual charging unit at a station.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| id | number | yes | Auto-generated by json-server |
| station_id | number | yes | FK to `Station.id` |
| type | string | yes | Connector type: `AC` or `DC` |
| power_kw | number | yes | Power rating in kilowatts |
| status | string | yes | One of: `available`, `in_use`, `maintenance` |

**Relationships**: Belongs to one `Station`

---

### Design Token (conceptual)

A named visual value in the shared design system. Not a runtime entity — these are TypeScript constants.

| Category | Token Group | Format | Files |
|----------|-------------|--------|-------|
| Color | brand, surface, text, border, status, neutral | Hex string | `colors.ts`, `native.ts` |
| Typography | fontFamily, fontSize, fontWeight | CSS/RN values | `typography.ts` |
| Spacing | 4–96px scale | Number (px) | `spacing.ts` |
| Radius | sm–full scale | Number (px) | `radius.ts` |
| Shadow | card, panel, float, pin | CSS shadow / RN style | `shadows.ts` |

## State Transitions

For MVP-1, station and charger status values are static in seed data. No runtime state machine is implemented. The status field serves as data for the driver apps to render correct visual indicators (status badge colors defined in design tokens).

## Validation Rules (MVP-1 scope)

- `station.partner_id` must reference an existing `partner.id`
- `charger.station_id` must reference an existing `station.id`
- Station coordinates must be valid lat/lng for Tunisia
- All status fields must be one of: `available`, `in_use`, `maintenance`
- `charger.power_kw` must be a positive number
