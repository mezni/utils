# Implementation Plan: Admin Portal — Shell, Navigation & BaseMap

**Branch**: `007-admin-portal-shell` | **Date**: 2026-05-26 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/007-admin-portal-shell/spec.md`

## Summary

Build the BorneMap Admin Portal frontend with a persistent AppShell layout (sidebar + content area), six-section navigation (Overview, Users, Data, Analytics, Security, Settings), an interactive Leaflet BaseMap centered on Tunisia with station markers, a design token system shared via `packages/ui`, and an Overview Dashboard with metric chips and skeleton loading placeholders. Implements sandbox workspace toggle with localStorage persistence.

## Technical Context

**Language/Version**: TypeScript 5.x, React 18.x, Node.js 20 LTS

**Primary Dependencies**: React Router v6 (nested routes), Leaflet + react-leaflet v4 (map), Tailwind CSS v3 (styling), Vite (bundler)

**Storage**: localStorage (sandbox toggle preference)

**Testing**: Vitest + @testing-library/react

**Target Platform**: Desktop web browsers (1024px+ minimum viewport)

**Project Type**: Web application (single-page admin portal)

**Performance Goals**: Overview Dashboard loads within 3 seconds on standard connection; sandbox toggle responds within 1 second

**Constraints**: Hardcoded hex codes banned — all styling via Tailwind design tokens; ScrollableTable enforces 800px min-width; ConfirmDeleteModal requires exact ID match; map tiles from CartoDB

**Scale/Scope**: Single admin user, ~100 station markers on map, 6 navigation sections

## Phase 0 — Research & Technical Decisions

### Technology Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Map library | Leaflet + react-leaflet v4 | Per constitution (Platform Constraints); lightest-weight tile map for React; CartoDB tile support built-in |
| Routing | React Router v6 with `<Outlet/>` | Existing project convention (per spec assumptions); nested routes match sidebar section structure |
| Design tokens | Tailwind config with CSS custom properties | Per docs/03-web-admin-ux-spec.md; centralized in `packages/ui/tailwind.config.cjs` |
| State management | React hooks + context (no Redux) | Admin portal is low-complexity; sandbox toggle via localStorage + React state is sufficient |
| Bundle tool | Vite | Already configured in existing admin-portal scaffold |
| Testing | Vitest + @testing-library/react | Existing frontend toolchain; Vitest is Vite-native |
| Loading states | Skeleton placeholders | Clarified in spec Q2 — skeleton shapes for metric chips and map area |
| Marker popup | Popup with info + "View Details" link | Clarified in spec Q1 — prevents losing map context |
| Sandbox persistence | localStorage | Clarified in spec Q3 — preference survives page reloads |
