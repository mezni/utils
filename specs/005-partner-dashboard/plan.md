# Implementation Plan: Partner Dashboard — Multi-Tenant Views

## Summary

Build a multi-tenant partner dashboard web application that allows partner operators to view and manage only their own EV charging stations and chargers. The dashboard reuses existing auth (JWT), UI components (`@bornemap/ui`), and backend CRUD endpoints with added `owner_id` scoping. It includes four navigation sections: Overview, Stations (with BaseMap), Chargers, and Profile.

## Technical Context

**Language/Version**: TypeScript 5.x (frontend), Rust 1.75+ (backend)

**Primary Dependencies**:
- Frontend: React 18 + Vite 5, Tailwind CSS, Leaflet/React-Leaflet, React Router
- Backend: Actix-web 4, SQLx, Tokio, `nanoid` crate
- Shared: `@bornemap/ui` design system (existing package)

**Storage**: PostgreSQL 16+ with PostGIS (existing)

**Testing**: `pnpm -r type-check` / `pnpm -r lint` / `pnpm -r build` (frontend); `cargo test` / `cargo clippy` (backend)

**Target Platform**: Web (modern browsers via Vite build)

**Project Type**: Web application (frontend app + backend API extension)

**Performance Goals**: Station/charger list loads within 3 seconds (matching SC-001); marker map renders without perceptible lag

**Constraints**: All constitutional rules apply — semantic IDs (`PRT-`/`STN-`/`CHG-`), soft-delete for stations, `owner_id` injection at repository layer, ConfirmDeleteModal for destructive actions

**Scale/Scope**: Supports multiple partner orgs with up to ~100 stations per partner (matching seed data scale)

**Structure Decision**: Option 2 — Web application (frontend + backend). All shared UI components come from `packages/ui/`. The backend changes are additive (adding WHERE clauses, locking owner_id) — no new tables or endpoints required.
