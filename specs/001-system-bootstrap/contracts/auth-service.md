# Contract: auth-service

**Service**: auth-service
**Port**: 3000
**Responsible for**: Authentication, user profile management, Keycloak integration

## Overview

auth-service provides authentication and user profile management APIs. It manages user credentials through Keycloak and provides user profile queries.

## Service Responsibilities

### Owned APIs

- User authentication (via Keycloak)
- User profile retrieval
- User profile updates

### Operational APIs

- `/health` — Service health check
- `/ready` — Service readiness check
- `/live` — Service liveness check
- `/metrics` — Prometheus metrics (optional)

### NO Direct Database Access

- auth-service owns platform_db.users table
- DOES NOT have direct database write access
- All data operations go through Keycloak

## Data Access

### Keycloak Integration

**Database**: keycloak_db (auto-generated by Keycloak)

**Access Pattern**:
- User authentication via Keycloak OpenID Connect
- User profiles stored in Keycloak user attributes
- No application-level database queries

## Constraints

### Identity System

- Users identified by UUID (Keycloak sub)
- Entities identified by nanoid(12) with PREFIX (STA/CHG/OPR/EVT)
- No mixing of identity systems

### Data Ownership

- Platform DB users table owned by auth-service (READ/WRITE)
- No cross-service writes allowed
- admin-service can READ user profiles but NOT modify

### Contract-First

- DTOs defined in `domain-types` crate
- No runtime logic in domain-types
- API contracts defined before implementation

## Migration Isolation

- SQLx compile-time verification required
