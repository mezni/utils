# CHANGE POLICY

---

## 1. Allowed Changes

- adding new epics
- extending existing epics (non-breaking)
- adding new endpoints (within version rules)

---

## 2. Forbidden Changes

- modifying core architecture rules without constitution update
- introducing UUID system
- bypassing Clean Architecture layers
- changing external identity model

---

## 3. Change Classification

### Minor Change
- UI updates
- new endpoints
- new optional fields

### Major Change
- schema restructuring
- API contract changes
- identity model changes

---

## 4. Approval Rule

No change is valid unless:
- documented in change record
- compliant with constitution
