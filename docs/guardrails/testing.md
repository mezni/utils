# Guardrail — Testing

Applies to: all services (`services/`), shared crates (`crates/`), and frontend packages (`apps/`, `packages/`)

---

## Testing philosophy

Every feature ships with tests. Tests are not written after the fact — they are part of the definition of done. A PR without tests for new logic is incomplete, not just low-quality.

Three layers, all required:

| Layer | Scope | Tooling | Location |
|-------|-------|---------|----------|
| Unit | Single function or type in isolation | Rust built-in, Vitest | `src/` inline (`#[cfg(test)]`) or `tests/unit/` |
| Integration | One service end-to-end against a real DB | `sqlx` test helpers, `actix-web::test` | `tests/integration/` |
| E2E | Full stack: client → Traefik → service → DB | Playwright | `tests/e2e/` |

---

## Unit tests (Rust)

Unit tests live inline in the same file as the code they test, inside `#[cfg(test)]` blocks.

```rust
// service/station_service.rs

#[cfg(test)]
mod tests {
    use super::*;
    use crate::repository::MockStationRepository;  // generated by mockall

    #[tokio::test]
    async fn create_station_busts_cache_on_success() {
        let mut mock_repo = MockStationRepository::new();
        let mock_cache = Arc::new(MockCacheClient::new());

        mock_repo
            .expect_create()
            .returning(|_| Ok(station_fixture()));

        mock_cache
            .expect_invalidate_nearby()
            .times(1)
            .returning(|_, _| Ok(()));

        let svc = StationService { repo: mock_repo, cache: mock_cache.clone() };
        let result = svc.create_station(new_station_fixture()).await;

        assert!(result.is_ok());
    }

    #[tokio::test]
    async fn create_station_returns_validation_error_on_invalid_coords() {
        let svc = StationService { repo: MockStationRepository::new(), cache: Arc::new(MockCacheClient::new()) };
        let mut input = new_station_fixture();
        input.latitude = 999.0;  // invalid

        let err = svc.create_station(input).await.unwrap_err();
        assert!(matches!(err, AppError::Validation(_)));
    }
}
```

Rules:
- Use `mockall` to generate mocks for all repository and cache traits.
- Every service method gets at minimum: one happy-path test, one error-path test.
- Fixtures go in `tests/fixtures.rs` or a `fixtures` module — never inline large structs in test bodies.
- Never use `tokio::test` with `#[test]` — pick one.
- Test function names follow `<unit>_<condition>_<expected_result>` convention.

## Integration tests (Rust)

Integration tests run against a real PostgreSQL instance (Docker Compose test profile). They test the full request lifecycle: handler → service → repository → DB.

```rust
// tests/integration/station_test.rs

use actix_web::test;

#[sqlx::test(fixtures("partners", "stations"))]
async fn get_nearby_returns_stations_within_radius(pool: PgPool) {
    let app = test::init_service(build_app(pool)).await;

    let req = test::TestRequest::get()
        .uri("/api/v1/nearby?lat=36.8189&lng=10.1658&radius=1000")
        .insert_header(("Authorization", "Bearer " + &test_jwt("role:driver")))
        .to_request();

    let resp = test::call_service(&app, req).await;
    assert_eq!(resp.status(), 200);

    let body: NearbyResponse = test::read_body_json(resp).await;
    assert!(!body.stations.is_empty());
}

#[sqlx::test]
async fn create_station_without_partner_role_returns_403(pool: PgPool) {
    let app = test::init_service(build_app(pool)).await;

    let req = test::TestRequest::post()
        .uri("/api/v1/admin/stations")
        .insert_header(("Authorization", "Bearer " + &test_jwt("role:driver")))  // wrong role
        .set_json(new_station_payload())
        .to_request();

    let resp = test::call_service(&app, req).await;
    assert_eq!(resp.status(), 403);
}
```

Rules:
- Use `sqlx::test` macro — it creates an isolated DB per test and rolls back automatically.
- Fixtures are SQL files in `tests/fixtures/` (e.g. `partners.sql`, `stations.sql`).
- `test_jwt(role)` is a shared helper that mints a signed test JWT with the given role — never hardcode a token string.
- Every endpoint gets at minimum: happy path, missing auth (401), wrong role (403), invalid input (422).
- Integration tests must not call external services. Mock Keycloak JWKS with a local test key pair.

## E2E tests (Playwright)

E2E tests live in `tests/e2e/` and run against a full Docker Compose stack (all services + Keycloak + DB + Redis + Traefik).

```typescript
// tests/e2e/station-discovery.spec.ts
import { test, expect } from '@playwright/test';
import { loginAs } from './helpers/auth';

test('driver can see nearby stations on the map', async ({ page }) => {
  await loginAs(page, 'driver');
  await page.goto('/map');

  // Map loads with shimmer skeleton, not blank
  await expect(page.locator('[data-testid="map-skeleton"]')).toBeVisible();

  // Stations appear after load
  await expect(page.locator('[data-testid="station-marker"]').first()).toBeVisible({ timeout: 5000 });
});

test('unauthenticated user sees public map but cannot favourite', async ({ page }) => {
  await page.goto('/map');
  await page.locator('[data-testid="station-marker"]').first().click();
  await expect(page.locator('[data-testid="favourite-btn"]')).not.toBeVisible();
});

test('partner can create a new station from dashboard', async ({ page }) => {
  await loginAs(page, 'partner');
  await page.goto('/dashboard/stations/new');
  await page.fill('[data-testid="station-name"]', 'Test Station Tunis');
  await page.fill('[data-testid="lat"]', '36.8189');
  await page.fill('[data-testid="lng"]', '10.1658');
  await page.click('[data-testid="submit-btn"]');
  await expect(page.locator('[data-testid="success-toast"]')).toBeVisible();
});
```

Rules:
- Every user-facing flow defined in the MVP spec needs at least one E2E test.
- Use `data-testid` attributes for selectors — never CSS classes or text content.
- `loginAs(page, role)` is a shared helper that authenticates via the Auth Service (not directly via Keycloak UI).
- E2E tests are run in CI on every PR to `main`, not on feature branches (too slow).
- Flaky tests are blocking. A flaky E2E test must be fixed or deleted — never skipped.

## Frontend unit tests (Vitest)

```typescript
// packages/shared-hooks/__tests__/useNearby.test.ts
import { renderHook, waitFor } from '@testing-library/react';
import { useNearby } from '../useNearby';
import { server } from '../mocks/server';  // msw
import { http, HttpResponse } from 'msw';

test('useNearby returns stations on success', async () => {
  server.use(
    http.get('/api/v1/nearby', () =>
      HttpResponse.json({ stations: [stationFixture()] })
    )
  );

  const { result } = renderHook(() => useNearby({ lat: 36.8, lng: 10.1, radius: 1000 }));

  await waitFor(() => expect(result.current.status).toBe('success'));
  expect(result.current.data?.stations).toHaveLength(1);
});

test('useNearby exposes error state on 500', async () => {
  server.use(http.get('/api/v1/nearby', () => HttpResponse.error()));

  const { result } = renderHook(() => useNearby({ lat: 36.8, lng: 10.1, radius: 1000 }));

  await waitFor(() => expect(result.current.status).toBe('error'));
});
```

Rules:
- Use `msw` (Mock Service Worker) for all API mocking — never mock `fetch` directly.
- Every shared hook gets: success, error, and loading state tests.
- Every shared UI component gets a snapshot test + interaction test for each interactive state.
- `data-testid` attributes on all interactive elements — same as E2E.

## Coverage thresholds (CI enforced)

| Layer | Minimum coverage |
|-------|-----------------|
| Rust unit (service + domain) | 85% line coverage |
| Rust integration (handlers) | 100% of endpoints covered |
| TypeScript hooks and utils | 80% line coverage |
| E2E critical flows | 100% of flows in MVP spec |

---

## Self-check before submitting

- [ ] Every new service method has a unit test (happy + error path)
- [ ] Every new endpoint has an integration test (200 + 401 + 403 + 422)
- [ ] Every new user-facing flow has an E2E test
- [ ] `sqlx::test` used for all integration tests (not a shared pool)
- [ ] No hardcoded tokens or credentials in test files
- [ ] `data-testid` added to every new interactive element
- [ ] All tests pass locally before submitting (`cargo test`, `vitest run`, `playwright test`)
