# ADR-003: MapContainer Abstraction

## Status

**ACCEPTED**

## Context

BorneMap needs:

- Single map rendering code across platforms
- Different mapping libraries per platform
- Consistent behavior and UX
- Easy testing of map components
- No vendor lock-in

## Decision

**Implement MapContainer abstraction with platform adapters**

## Rationale

1. **Platform Independence**: Single codebase for mobile and web
2. **Library Switching**: Easy to switch mapping library if needed
3. **Testing**: Test map behavior independently of library
4. **Consistency**: Same API across all platforms
5. **MapContainer Abstraction**: All map rendering goes through MapContainer

## Consequences

**Positive:**
- ✅ Single codebase for mobile and web
- ✅ Easy to switch mapping library
- ✅ Map logic can be tested independently
- ✅ Consistent behavior across platforms
- ✅ No direct map library usage in apps

**Negative:**
- ❌ Additional abstraction layer
- ❌ Slightly more code
- ❌ Learning curve for abstraction pattern

## Alternatives Considered

### Option 1: Platform-Specific Components
- ❌ Duplicate map logic
- ❌ Different behavior per platform
- ❌ Hard to maintain
- ❌ Testing is harder

### Option 2: Direct Map Library Usage
- ❌ Code duplication across platforms
- ❌ Hard to switch libraries
- ❌ Testing is platform-specific
- ❌ Violates architecture discipline

### Option 3: MapContainer Abstraction (CHOSEN)
- ✅ Single codebase
- ✅ Consistent behavior
- ✅ Easy library switching
- ✅ Platform independence

## Architecture

```typescript
// ✅ CORRECT - Using MapContainer abstraction
import { MapContainer, MapMarker } from '@bm/components';
import { Station } from '@bm/types';

function StationMap({ stations }: { stations: Station[] }) {
  return (
    <MapContainer>
      {stations.map(station => (
        <MapMarker
          key={station.id}
          station={station}
          onPress={() => onSelect(station)}
        />
      ))}
    </MapContainer>
  );
}
```

### Platform Adapters

```typescript
// MapContainer Native (React Native)
import { View } from 'react-native';

export const MapContainer = ({
  children,
  style,
}: {
  children: React.ReactNode;
  style: ViewStyle;
}) => {
  return (
    <View style={style}>
      {children}
    </View>
  );
};

// MapContainer Web (Leaflet)
import { useEffect, useRef } from 'react';
import L from 'leaflet';

export const MapContainer = ({
  children,
  style,
  onMapReady,
}: {
  children: React.ReactNode;
  style: React.CSSProperties;
  onMapReady?: (map: L.Map) => void;
}) => {
  const mapRef = useRef<L.Map | null>(null);

  useEffect(() => {
    if (mapRef.current) return;

    mapRef.current = L.map('map').setView([51.505, -0.09], 13);

    L.tileLayer('https://{s}.tile.openstreetmap.org/{z}/{x}/{y}.png', {
      attribution: '© OpenStreetMap',
    }).addTo(mapRef.current);

    onMapReady?.(mapRef.current);
  }, []);

  return <div ref={mapRef.current} style={style}>{children}</div>;
};
```

## Prevention Rules

1. **All Map Rendering Must Use MapContainer**
   - No direct map library usage
   - No platform-specific map code in apps
   - All map components through abstraction

2. **Platform Logic in Adapters Only**
   - React Native logic in MapContainer.native.ts
   - Web logic in MapContainer.web.ts
   - No platform code in apps

3. **Consistent Behavior Across Platforms**
   - Same API across platforms
   - Same behavior for same inputs
   - Same UX patterns
   - Same design tokens

4. **Map Interactions Handled by MapContainer**
   - Marker selection
   - Pan and zoom
   - Tapping markers
   - All map interactions handled by abstraction
