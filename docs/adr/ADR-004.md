# ADR-004: PostGIS for Geospatial Data

## Status

**ACCEPTED**

## Context

BorneMap needs:

- Geospatial queries (nearby stations, distance calculations)
- Spatial indexing for performance
- Spatial data integrity
- Distance-based filtering
- Map-based interactions

## Decision

**Use PostGIS extension for all geospatial operations**

## Rationale

1. **PostGIS Integration**: Built-in geospatial extension for PostgreSQL
2. **Performance**: Spatial indexing (GiST, GIST) for fast queries
3. **Functionality**: Comprehensive spatial functions (distance, nearest, bounding box, etc.)
4. **Standard**: OGC standards compliance
5. **Maturity**: Battle-tested geospatial database
6. **Rust Support**: Excellent Rust PostGIS bindings
7. **GIS Isolation**: GIS is read-only (protected by architecture rules)

## Consequences

**Positive:**
- ✅ Fast geospatial queries with spatial indexing
- ✅ Distance calculations for nearby stations
- ✅ Spatial filtering with simple WHERE clause
- ✅ Integration with Rust backend
- ✅ Professional-grade geospatial capabilities
- ✅ Read-only access (GIS is read-only)
- ✅ Spatial data integrity constraints

**Negative:**
- ❅ Additional PostgreSQL extension overhead
- ❅ PostgreSQL required (not MySQL or SQLite)
- �️ Need geospatial training for developers

## Alternatives Considered

### Option 1: Standard SQL with Manual Calculations
- ❌ Slow distance calculations
- ❌ No spatial indexing

### Option 2: MySQL Spatial Extensions
- ❌ Less mature geospatial support

### Option 3: No Database for Geospatial
- ❌ All in-memory

- ❅ No indexing

### Option 4: PostGIS (CHOSEN)
- ✅ Best performance with spatial indexing
- ✅ Comprehensive spatial functions
- ✅ Excellent Rust support
- ✅ OGC standards compliance
- ✅ Professional-grade geospatial

## Architecture

### PostGIS Database Schema

```sql
-- stations table with spatial data
CREATE TABLE stations (
    id BIGSERIAL PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    description TEXT,
    address VARCHAR(500),
    latitude DECIMAL(10, 8) NOT NULL,
    longitude DECIMAL(11, 8) NOT NULL,
    category VARCHAR(50),
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW(),

    -- Spatial column with GiST index
    location GEOGRAPHY(POINT, 4326) NOT NULL
);

-- GiST index for fast spatial queries
CREATE INDEX idx_stations_location ON stations
    USING GIST (location);

-- Distance index for common queries
CREATE INDEX idx_stations_nearby ON stations
    USING GIST (location);
```

### Geospatial Query Examples

#### Nearby Stations Query

```rust
const POSTGIS_NEARBY_QUERY: &str = r#"
    SELECT *,
        ST_Distance(
            ST_SetSRID(ST_MakePoint($1, $2), 4326)::geography,
            ST_SetSRID(ST_MakePoint(lon, lat), 4326)::geography
        ) AS distance
    FROM stations
    WHERE ST_DWithin(
        ST_SetSRID(ST_MakePoint($1, $2), 4326)::geography,
        ST_SetSRID(ST_MakePoint(lon, lat), 4326)::geography,
        $3
    )
    ORDER BY distance ASC
    LIMIT 50
"#;
```

#### Simple Spatial Filter

```rust
const POSTGIS_WITHIN_QUERY: &str = r#"
    SELECT *
    FROM stations
    WHERE ST_Within(
        ST_SetSRID(ST_MakePoint($1, $2), 4326)::geography,
        ST_SetSRID(ST_MakePoint(lon, lat), 4326)::geography,
        $3
    )
    ORDER BY created_at DESC
    LIMIT 100
"#;
```

#### Bounding Box Query

```rust
const POSTGIS_BBOX_QUERY: &str = r#"
    SELECT *
    FROM stations
    WHERE ST_Intersects(
        ST_SetSRID(ST_MakePoint($1, $2), 4326)::geography,
        ST_SetSRID(ST_MakePoint(lon, lat), 4326)::geography
    )
    ORDER BY created_at DESC
    LIMIT 100
"#;
```

    }

## Prevention Rules

1. **GIS Isolation**
   - GIS is read-only (protected by architecture rules)
   - No writes to gis tables
   - Only Read operations allowed
   - Write operations blocked at architecture level

2. **PostGIS Isolation**
   - All geospatial queries in repository layer
   - No raw SQL in services
   - Use repository abstraction
   - Test repository queries independently

3. **Distance Calculations in Database**
   - Always calculate distance in PostGIS
   - Never calculate in application
   - Use `ST_Distance` function
   - Use `ST_DWithin` for filtering

4. **Spatial Indexing**
   - Always create GiST indexes on spatial columns
   - Use spatial indexes for filtering
   - Test query performance with indexes
   - Monitor query execution plans

5. **Unit of Measurement**
   - Always use degrees for geospatial queries
   - Use `GEOGRAPHY` for distance calculations
   - Use `GEOMETRY` for coordinates only
   - Always use WGS84 (SRID 4326)
