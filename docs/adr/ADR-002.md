# ADR-002: Rust for Backend Services

## Status

**ACCEPTED**

## Context

BorneMap needs:

- Type-safe backend services
- High-performance geospatial queries
- Memory efficiency for mobile apps
- Rust ecosystem maturity

## Decision

**Use Rust for all backend services**

## Rationale

1. **Performance**: Rust offers exceptional performance with minimal overhead
2. **Memory Safety**: Compile-time memory safety prevents runtime errors
3. **Type Safety**: Strong typing catches errors at compile time
4. **Geospatial**: Excellent PostGIS support with Rust bindings
5. **Concurrency**: Async runtime for high concurrency
6. **Safety**: No garbage collection for mobile backend performance
7. **Community**: Mature ecosystem with PostGIS, Tokio, Diesel

## Consequences

**Positive:**
- ✅ High performance for geospatial queries
- ✅ Memory safety with no runtime crashes
- ✅ Type safety catches errors at compile time
- ✅ Excellent PostGIS support
- ✅ Memory efficient (no GC pauses)
- ✅ Strong typing for API responses
- ✅ Async runtime for high concurrency

**Negative:**
- ❌ Steeper learning curve for developers
- ❌ Larger binary sizes compared to Go
- ❌ Less community compared to Node.js/Go
- ❌ No runtime garbage collection

## Alternatives Considered

### Option 1: Node.js (Express/Fastify)
- ❌ Poor geospatial performance
- ❌ Memory issues with large datasets
- ❌ No compile-time type safety
- ❌ GC pauses affect responsiveness

### Option 2: Go
- ❌ Less mature PostGIS ecosystem
- ❌ No memory safety guarantees
- ❌ Smaller community for geospatial
- ❌ Less type safety than Rust

### Option 3: Python (FastAPI)
- ❌ Poor performance
- ❌ Memory management issues
- ❌ No compile-time safety
- ❌ Not suitable for mobile backend

### Option 4: Rust (CHOSEN)
- ✅ Best performance for geospatial
- ✅ Memory safety without GC
- ✅ Type safety at compile time
- ✅ Excellent PostGIS support
- ✅ Memory efficient
- ✅ Strong async runtime

## Architecture

### Clean Architecture in Rust

```rust
// ❌ WRONG - Layers mixed
#[derive(Serialize)]
pub struct StationsResponse {
    pub stations: Vec<StationDto>,  // Service layer logic
}

// ✅ CORRECT - Clean architecture
// Handler layer
#[derive(Serialize)]
pub struct StationsResponse {
    pub stations: Vec<StationDto>,
}

// Service layer
impl StationsService {
    pub async fn nearby(&self, params: NearbyParams) -> Result<Vec<Station>> {
        self.repository
            .find_nearby(params)
            .await?
            .into_iter()
            .map(Station::from)
            .collect()
    }
}

// Repository layer
impl StationsRepository {
    pub async fn find_nearby(&self, params: NearbyParams) -> Result<Vec<StationEntity>> {
        self.db
            .query(POSTGIS_NEARBY_QUERY, params)
            .await
    }
}
```

### Repository Pattern with PostGIS

```rust
const POSTGIS_NEARBY_QUERY: &str = r#"
    SELECT *,
        ST_Distance(
            ST_SetSRID(ST_MakePoint($1, $2), 4326)::geography,
            ST_SetSRID(ST_MakePoint(lon, lat), 4326)::geography
        ) AS distance
    FROM stations
    WHERE ST_DWithin(
        ST_SetSRID(ST_MakePoint($1, $2), 4326)::geography,
        ST_SetSRID(ST_MakePoint(lon, lat), 4326)::geography,
        $3
    )
    ORDER BY distance ASC
    LIMIT 50
"#;
```

## Implementation

```rust
// ✅ CORRECT: Handler → Service → Repository pattern
use axum::{extract::State, response::Json};
use sea_orm::{Database, EntityTrait, QuerySelect, IntoActiveModel};

pub async fn nearby_stations(
    State(service): State<Arc<StationsService>>,
    Query(params): Query<NearbyParams>,
) -> Result<Json<StationsResponse>, AppError> {
    let stations = service.nearby(params).await?;
    Ok(Json(StationsResponse { stations }))
}

// Service layer
pub struct StationsService {
    repository: Arc<StationsRepository>,
}

impl StationsService {
    pub async fn nearby(&self, params: NearbyParams) -> Result<Vec<StationDto>> {
        self.repository
            .find_nearby(params)
            .await?
            .into_iter()
            .map(Station::from)
            .collect()
    }
}

// Repository layer
pub struct StationsRepository {
    db: Database,
}

impl StationsRepository {
    pub async fn find_nearby(&self, params: NearbyParams) -> Result<Vec<StationEntity>> {
        self.db
            .query(POSTGIS_NEARBY_QUERY, (params.latitude, params.longitude, params.radius))
            .await
    }
}
```

## Prevention Rules

1. **Clean Architecture Enforcement**
   - Handler → Service → Repository layer separation
   - No business logic in handlers
   - No data access logic in services
   - No presentation logic in repositories

2. **PostGIS Isolation**
   - All geospatial queries in repository layer
   - No raw SQL in services
   - Use repository abstraction
   - Test repository queries independently

3. **Type Safety at All Layers**
   - All types from `@bm/types`
   - No custom types outside shared packages
   - Compile-time type checking
   - No `any` types

4. **Error Handling**
   - Use typed errors (`AppError`)
   - Never use `unwrap()` or `expect()`
   - Always handle errors explicitly
   - Return typed error responses
