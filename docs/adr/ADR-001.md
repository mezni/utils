# ADR-001: React Query for Server State

## Status

**ACCEPTED**

## Context

BorneMap needs a robust client-server state management solution for:

- Server state (stations, locations, map data)
- Caching and revalidation strategies
- Optimistic updates
- Loading/error states

## Decision

**Adopt React Query for all server-side state management**

## Rationale

1. **Performance**: Automatic caching, background updates, optimistic updates
2. **Type Safety**: TypeScript integration with strong typing
3. **Declarative**: Query + Mutation API for simple operations
4. **Community**: Mature ecosystem with extensive documentation
5. **Frontend Architecture**: Aligns with strict state separation (UI: Zustand, Server: React Query)

## Consequences

**Positive:**
- ✅ Improved performance with caching
- ✅ Better UX with optimistic updates
- ✅ Consistent error handling
- ✅ Loading states automatically managed
- ✅ Backend integration with typed responses

**Negative:**
- ❌ Additional dependency (`@tanstack/react-query`)
- ❌ Learning curve for React Query
- ❌ Server state must be server-generated
- ❌ No client-only state (use Zustand instead)

## Alternatives Considered

### Option 1: Context API + Custom Hooks
- ❌ No built-in caching
- ❌ Manual loading state management
- ❌ No optimistic updates
- ❌ No background refetching

### Option 2: Redux Toolkit
- ❌ Overkill for server state
- ❌ Boilerplate required
- ❌ Complex debugging
- ❌ Learning curve

### Option 3: Apollo Client
- ❌ GraphQL requirement
- ❌ Overcomplicated for REST APIs
- ❌ Additional GraphQL complexity

### Option 4: React Query (CHOSEN)
- ✅ Built for REST APIs
- ✅ Automatic caching
- ✅ Optimistic updates
- ✅ Background refetching
- ✅ TypeScript support

## Implementation

```typescript
// ✅ CORRECT: Using React Query for server state
import { useQuery } from '@tanstack/react-query';
import { apiClient } from '@bm/api-client';
import { Station } from '@bm/types';

const useStations = (params: StationQueryParams) => {
  return useQuery({
    queryKey: ['stations', params],
    queryFn: () => apiClient.stations.list(params),
    // Server state is managed by React Query
    // Loading, error, and data states are automatic
  });
};
```

## Prevention Rules

1. **No Client State in React Query**
   - UI state must use Zustand only
   - Server state must use React Query only
   - No mixing between the two

2. **Cache Keys Must Be Stable**
   - Use primitive keys (strings, numbers)
   - Avoid object/array keys
   - Only regenerate on data changes

3. **Always Use Typed Responses**
   - Use `@bm/types` for all responses
   - No `any` types
   - Strict typing enforced

4. **Optimistic Updates for Fast Feedback**
   - Always use optimistic updates for mutations
   - Never show loading state for immediate actions

## Validation

- [ ] All server state uses React Query
- [ ] All cache keys are stable
- [ ] All responses are typed
- [ ] No client state in React Query
- [ ] Optimistic updates used for mutations
